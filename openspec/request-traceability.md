# Request Traceability Reference

This reference traces each sample request in mock_data/requests.json through the four tool specifications:
- check_budget
- check_vendor_duplication
- check_policy_compliance
- assess_risk

Conventions used in this trace:
- All four tools are called for every request.
- check_budget returns structured output for valid cost centers: within_budget, remaining_budget, and overage.
- check_budget returns a structured error for unknown cost_center_id values.
- check_vendor_duplication POL-001 deny trigger is active only when total_amount > 25000 and conflicting active contracted vendors exist in-category.
- check_policy_compliance evaluates POL-001 through POL-008 and returns violations with forced_decision deny or escalate.
- assess_risk returns compliance flag status, contract status, and risk level in low/medium/high/critical.
- Decision precedence: escalate overrides deny, deny overrides approve.

## Session 4 Assertion Guidance

- Assert all four tools are invoked for every request.
- Assert check_budget output includes within_budget, remaining_budget, and overage for valid cost centers.
- Assert unknown cost centers return a structured error response.
- Assert policy violations include policy_id, violated_rule, and forced_decision for deny/escalate.
- Assert precedence behavior where both deny and escalate signals appear (for example REQ-002, REQ-006, REQ-008, REQ-010, REQ-014).
- If test labels are based on mock_data/requests.json expected_outcome, reconcile those labels against this spec-driven precedence table before final test lock-in.
